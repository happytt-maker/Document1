# 评测方案设计

> 目标：让「填得准不准」这件事可以被量化，且结果稳定可比。

## 1. 要测什么

| 指标 | 定义 | 目标 |
|---|---|---|
| 单表准确率 | 正确填写的字段数 / 应填字段总数 | ≥ 80% |
| 单文档响应时间 | 从提交到输出结果 | ≤ 90 秒 |
| 平均准确率 | 多张模板表的准确率均值 | 越高越好 |

## 2. 字段怎么算对

需要区分三种情况：

1. **完全正确**：与参考答案完全一致（数值允许公差，文本允许去空格后一致）
2. **部分正确**：语义对但格式不符（如日期写法不同）—— 是否计分需明确
3. **错误 / 空缺**：填错或没填

> 关键问题：模板中的空白单元格不计分，还是计为错误？
> 这直接影响策略——若计分，宁可填错也不能留空；若不计分，拿不准就留空。

## 3. 评测集规模

统计上，要判断两个方案之间 2% 的准确率差异是否有意义，样本量不能太小。

粗略估计：

- 若每个方案在 200 个字段上评测，标准误约 3.5%，2% 的差异完全淹没在噪声里
- 要到 400–600 个字段，2% 的差异才具备一定区分度

**建议**：按「每类边界用例 × 10」设计，优先覆盖：

| 类别 | 示例 |
|---|---|
| 数值精度 | 千分位、小数位、单位混写 |
| 日期写法 | 中英文格式混杂 |
| 同名异义 | 不同文档中的「编号」含义不同 |
| 缺失字段 | 源文档里根本没有这个信息 |
| 冲突信息 | 两份文档给的数值不一致 |
| 合并单元格 | 表头跨列、内容跨行 |

## 4. 评测流程

```
准备样本(文档 + 模板 + 参考答案)
        |
    自动运行系统
        |
    逐字段比对
        |
    输出明细表 + 汇总指标
        |
    按错误类型归类，定位改进点
```

## 5. 注意

- 参考答案必须人工核对，不能由系统自己生成
- 每次改动后重跑全量评测，不要只测几个案例
- 记录失败样本，沉淀成回归用例
