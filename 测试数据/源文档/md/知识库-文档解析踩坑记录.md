## 1. openpyxl 公式缓存问题

**现象**：读取含公式的单元格，得到 `None`。

**复现**：

```python
import openpyxl
wb = openpyxl.Workbook()
ws = wb.active
ws["A1"] = 100
ws["A2"] = 200
ws["A3"] = "=SUM(A1:A2)"
wb.save("test.xlsx")

wb1 = openpyxl.load_workbook("test.xlsx")
print(wb1.active["A3"].value)          # '=SUM(A1:A2)'  公式字符串

wb2 = openpyxl.load_workbook("test.xlsx", data_only=True)
print(wb2.active["A3"].value)          # None           缓存值是空的
```

**原因**：`data_only=True` 读的是「上次被 Excel 计算并保存时的值」。程序生成的文件从未被 Excel 打开过，缓存槽位是空的。

**应对**：
1. 判断字符串是否以 `=` 开头，是则标记为公式，不要当数值用
2. 需要数值时，自己实现一份简单求值（加减乘除、SUM、AVERAGE 覆盖大部分场景）
3. 不要在不了解数据来源时信任 `data_only=True`

## 2. python-docx 合并单元格重复

**现象**：表格有合并单元格时，遍历结果的单元格数量超过实际数量。

**复现**：

```python
from docx import Document

doc = Document()
table = doc.add_table(rows=2, cols=3)
table.cell(0, 0).merge(table.cell(0, 1))

for ri, row in enumerate(table.rows):
    for ci, cell in enumerate(row.cells):
        print(ri, ci, id(cell))
```

输出中 `id(cell)` 会重复出现。

**原因**：`row.cells` 是按网格展开的，合并区域内的每个网格坐标都返回同一个 `_Cell` 对象。

**影响**：
- 统计「一共有多少条记录」会偏多
- 按行号定位内容时坐标对不上
- 导出成 JSON 后出现重复条目

**错误应对（不要用）**：

```python
# 错误！id(cell) 不可靠
seen = set()
for ri, row in enumerate(table.rows):
    for ci, cell in enumerate(row.cells):
        if id(cell) in seen:
            continue
        seen.add(id(cell))
        # 处理 cell
```

**为什么错**：`row.cells` 每次访问都会**新建 `_Cell` 包装对象**。`id()` 拿到的是这层临时包装对象的地址，不是底层单元格的地址。

实测数据（6 行 4 列的表，实际应 23 个唯一单元格）：

| 坐标 | id(cell) | cell.text |
|---|---|---|
| (1,0) | 1527604609712 | `'吴晓敏\n吴晓敏'` |
| (2,0) | 1527604666192 | `'吴晓敏\n吴晓敏'` |

两行明明指向**同一个合并单元格**，`id()` 却完全不同 → 去重失效，唯一数算成 24。

**正确应对（用底层 XML 元素身份）**：

```python
seen = set()
for ri, row in enumerate(table.rows):
    for ci, cell in enumerate(row.cells):
        key = cell._tc          # 底层 CT_Tc 元素，这才是单元格的真实身份
        if key in seen:
            continue
        seen.add(key)
        # 处理 cell
```

实测结果：唯一数 = 23，正确。

> 注意：`seen` 里要保存元素**引用本身**（而不是 `id`），否则元素被 GC 回收后地址会被复用。

**另一个坑**：合并后的单元格 `cell.text` 是 `'吴晓敏\n吴晓敏'`——多个段落内容用 `\n` 拼起来了。定位内容时要按段落拆开，不能当成一个值。

**想拿到合并信息本身**，可以解析 XML 属性：

```python
tcPr = cell._tc.tcPr
if tcPr is not None:
    span = tcPr.gridSpan            # 横向合并了几列
    vmerge = tcPr.vMerge            # 纵向合并标记
```

## 3. cell.text 赋值破坏格式

**现象**：给 `cell.text` 赋值后，原来设置的字号、加粗、居中都丢了。

**原因**：`cell.text = "x"` 内部会先清空单元格内容再新建一个段落，原有的 run 级属性全部丢失。

**应对**：

```python
# 不要这样
cell.text = "新内容"

# 保留格式的写法
if cell.paragraphs and cell.paragraphs[0].runs:
    cell.paragraphs[0].runs[0].text = "新内容"
else:
    cell.paragraphs[0].text = "新内容"
```

**注意**：如果单元格有多个 run，赋值第一个 run 会保留其余 run 的内容，需要先清理。

## 4. 中文编码问题

**现象**：读文件时抛 `UnicodeDecodeError`。

**原因**：Windows 环境下部分 txt 是 GBK 编码，直接按 UTF-8 读会失败。

**应对**：

```python
def read_text(path):
    for enc in ("utf-8", "utf-8-sig", "gbk", "gb18030"):
        try:
            return open(path, encoding=enc).read()
        except UnicodeDecodeError:
            continue
    raise ValueError("无法识别文件编码: " + path)
```

**写文件时**：统一用 `encoding="utf-8"`，不要省略。

## 5. 日期格式不统一

**现象**：同一份材料里出现 `2026-03-15`、`2026年3月15日`、`2026/3/15`、`3/15/2026` 四种写法。

**应对**：抽取阶段先归一化，统一转成 `YYYY-MM-DD`。不要指望下游去兼容。
