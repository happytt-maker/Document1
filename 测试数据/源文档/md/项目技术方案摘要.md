# 文档理解与多源数据融合系统 · 技术方案摘要

> 版本：v0.3
> 更新日期：2026-03-20
> 编写：技术组

## 1. 背景

企业日常运营中，业务资料分散在 Word、Excel、PDF、纯文本等不同载体中，格式不统一、结构不规范。
当需要按照某张固定表格汇总信息时，通常只能依靠人工逐份翻阅、手工填写，耗时且容易出错。

本系统面向这一场景，目标是**输入一批异构文档 + 一张空白模板表，自动完成信息抽取与表格填写**。

## 2. 系统组成

系统由三个模块构成：

### 2.1 文档智能操作交互

通过自然语言指令对文档执行读取、查询、修改等操作。

- 输入：文档 + 自然语言指令
- 输出：操作结果 + 修改后的文档
- 关键要求：定位到具体段落/单元格，操作后不破坏原有格式

### 2.2 非结构化文档信息提取

从非结构化内容中抽取结构化字段，写入数据库。

| 字段类别 | 示例 | 来源 |
|---|---|---|
| 主体信息 | 单位名称、联系人 | 合同、纪要 |
| 数值信息 | 金额、数量、比例 | 台账、报表 |
| 时间信息 | 签订日期、截止日期 | 合同、制度 |
| 编号信息 | 合同编号、物料编码 | 各类文档 |

### 2.3 表格自定义数据填写

理解空白模板表的语义，自动填充内容。

- 模板在运行时才提供，**不能预置字段规则**
- 需要先理解表头含义，再决定去哪些文档找证据

## 3. 关键技术点

### 3.1 位置信息必须全程保留

> 这是整个系统的地基。

每个内容块必须记录来源位置：

| 格式 | 位置表示 |
|---|---|
| docx | 段落序号 / 表格-行-列 |
| xlsx | 工作表名!单元格坐标 |
| txt | 行号范围 |
| md | 行号范围 / 标题路径 |

### 3.2 程序负责计算，模型负责理解

- **模型**：理解语义、判断字段含义、在候选内容中做选择
- **程序**：精确读写文件、数值计算、格式校验
- **原则**：数值计算绝不交给模型，模型不擅长且无法保证稳定

### 3.3 已知技术风险

1. `openpyxl` 以 `data_only=True` 读取未经 Excel 打开的文件时，公式单元格返回 `None`
   - 原因：读取的是「上次保存时的缓存值」，程序生成的文件没有该缓存
   - 应对：识别公式字符串自行求值，或强制预计算

2. `python-docx` 遍历表格时，合并单元格会在多个坐标重复返回同一对象
   - 影响：统计行数、列数、项目数量会算错
   - 应对：用 `id()` 去重，或解析 `gridSpan` / `vMerge` 属性

3. 直接给 `cell.text` 赋值会重建段落，破坏原有 run 级格式
   - 应对：改写 `cell.paragraphs[0].runs[0].text`

## 4. 处理流程

```
扫描文档 -> 逐份解析 -> 提取内容块(带位置) -> 建立索引
                                              |
                                    上传模板表 -> 理解表头
                                              |
                          按字段检索证据 -> 组装答案 -> 写回表格
                                              |
                                        校验 -> 输出结果
```
