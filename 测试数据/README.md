## 已实测确认的坑（2026-09-28 生成时验证）

这三条是**实际跑出来的结论**，不是推测。开发时请对照检查。

### 坑 1：`data_only=True` 读公式返回 `None`

```
员工信息表 [员工信息] 公式数 = 16
  员工信息!I3 = "=G3+H3"
  员工信息!K3 = "=I3*12*J3"
销售台账   [销售台账] 公式数 = 11
库存盘点表 [库存明细] 公式数 = 10
项目进度跟踪表 [工时登记] 公式数 = 1     <- 多工作表，注意别漏

用 data_only=True 读 员工信息!I3  ->  None
```

**结论**：程序生成的文件、从未被 Excel 打开保存过的文件，公式缓存是空的。

**做法**：判断字符串以 `=` 开头 → 标记为公式；需要数值时自己实现简单求值。

### 坑 2：`id(cell)` 去重不可靠（重要！）

```
项目推进会会议纪要.docx  表0：6 行 × 4 列
  遍历总数 = 24
  用 id(cell) 去重后 = 24    <-- 错！应该 23
  用 cell._tc 去重后 = 23    <-- 正确
```

原因是 `row.cells` 每次访问都**新建 `_Cell` 包装对象**，`id()` 拿到的不是底层单元格的地址。

正确写法：

```python
seen = set()
for ri, row in enumerate(table.rows):
    for ci, cell in enumerate(row.cells):
        key = cell._tc        # 底层 XML 元素才是真实身份
        if key in seen:
            continue
        seen.add(key)
```

### 坑 3：合并单元格的内容会叠加

```
坐标 (1,0) 和 (2,0) 是同一个合并单元格
cell.text = '吴晓敏\n吴晓敏'      <-- 两行内容拼在一起
```

定位内容时要按段落拆开，不能当成一个值。
