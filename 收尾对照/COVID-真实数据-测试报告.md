# COVID-19 真实数据 · 智能填表测试报告（2026-11-03）

> 素材：`测试集\包含模板文件\COVID-19数据集\` 三件套
> - 模板 `COVID-19 模板.xlsx`（**只有表头 1 行**，6 列）
> - 源 `COVID-19全球数据集（节选）.xlsx`（15088 行 × 15 列，含「日期」列）
> - 源 `中国COVID-19新冠疫情情况.docx`（31 个省的叙述体，日期都是 2020-07-27）
> - 用户要求：**「智能填表，将两个文件的内容中日期一列从 2020/7/1 到 2020/8/31 的数据填入模板中」**

## 一、先说结论

| | 改之前 | 改之后 |
|---|---|---|
| 填进去几行 | **15 行** | **2542 行** |
| 这些行是什么 | 2020 年 **2 月**的 Albania（**区间外**） | 2020/7/1 ~ 8/31 的全部记录（41 国 × 62 天） |
| 「国家/地区」列第一条 | `国家/地区`（**把表头当数据填了**） | `Albania` |
| 日志怎么说 | 「成功：6/6 列」 | 行筛选命中 2542 行、0 次模型调用 |
| 逐格核对 | 无从核对（值本身错） | 15252 格**与源表逐格一致**（独立脚本重算，9 项全过） |
| 耗时 | 31.8 秒 | **18.6 秒**（读 8.5 + 模板 1.2 + 抽 4.5 + 写 3.1 + 验 1.3） |

一句话：**改之前它不是"填错"，是"根本没在做这件事，却报了成功"。** 这正是真实数据能暴露、而自己造的测试数据暴露不了的问题。

## 二、用户要求里藏了三个条件

原话 36 个字，其实定了三件事，以前一件都没实现：

| 条件 | 出处 | 以前 |
|---|---|---|
| ① **按日期区间筛行** | 「日期一列从 2020/7/1 到 2020/8/31」 | 完全没有这个概念。整份源表 15088 行都是"素材" |
| ② **按列名找同名列** | 隐含（模板列 ↔ 源列） | 靠大模型"理解"，列名一样也要它猜一遍 |
| ③ **多行铺开** | 2542 条记录要往下铺 | 模板只有表头时能补行，但抽取只给 15 条，补也就补 15 行 |

## 三、改之前的实测（基线，留证）

跑的是**未改动的代码**，源文档只放这两份（不混 16 份的池子），模板用刚上传的那张：

```
定源：主源 = 《COVID-19全球数据集（节选）.xlsx》 880 分（覆盖 5/6 列）
国家     ｜ 8.57 秒 ｜ 15 条
大洲     ｜ 12.15 秒｜ 14 条
人均GDP  ｜ 21.75 秒｜ 14 条
人口     ｜ 17.44 秒｜ 14 条
每日检测数｜ 18.01 秒｜ 14 条
病例数   ｜ 19.62 秒｜ 14 条
墙钟 31.78 秒 ｜ 成功 6/6 列 ｜ 一致性重审：各列来源一致 ✓
```

抽出来的东西（`结果\抽取结果-*.json`）：

```
国家  15 条 → 第一条 = "国家/地区"     ← 表头本身被当成数据
大洲  14 条 → Europe ×14               ← 全是 Albania 的
人均GDP 14 条 → 5353.2 ×14             ← 同上
病例数 14 条 → 首条出处 N15（不是 N2）  ← 行也没对齐
```

三个独立的问题叠在一起：

1. **数量级不对**：模型面对 15088 行，选择"总结"成 14~15 行 —— 它没有"整列搬"这个概念，
   输出长度也装不下 2542 行（`TABLE_MAX_ROWS = 400` 就是为这个设的上限）。
2. **口径不对**：它抽的是**表的前几行**（2020-02-25 起），跟「7/1~8/31」毫无关系 ——
   因为整条链路没有任何地方读过用户要求。
3. **对齐不对**：表头格被当成数据值填进「国家」列，病例数从 N15 起抽，14 条里一半错位。

**最危险的是第 4 点：日志全绿。** 6/6 列成功、来源一致、耗时 31.8 秒在线内、
验收报告"值一致 210/210 格"—— 因为验收比的是"写进去的 == 抽出来的"，
两边一起错的时候，它会理直气壮地说"可以交卷"。

## 四、根因与改法

### 4.1 根因：把"确定的搬运"交给了"不确定的模型"

模板 6 列在源表里都叫同样的名字（`国家/地区` 例外，模板写「国家」但结构读取器已识别出
斜线格拆成 国家/地区）。**列名一一对得上时，"抽"这个动作没有任何信息量** ——
答案是唯一的，让大模型去"理解"只会引入它能引入的所有错误。

所以正确的做法不是"把提示词写得更好"，是**这类活儿根本不该过模型**。

### 4.2 改了什么（4 处改动 + 2 个新模块）

| 文件 | 改动 | 一句话理由 |
|---|---|---|
| `matcher/rowscope.py` | **新增** 约 170 行 | 从用户要求里解析「列名 + 日期区间」，判断某行在不在区间内 |
| `matcher/direct.py` | **新增** 约 250 行 | 结构化直通：把池子里的 xlsx 格子还原成表，同名列整列搬、按行号对齐 |
| `matcher/run_all.py` | 加直通分支 | 有行条件 → 先试直通；对不上再回落大模型（**不偷偷切换**，日志写明） |
| `writer/fill.py` | `build_slot_map` 改"按名次对齐" | 筛完行的源行号不连续，用"行号差"会全部越界被丢掉 |
| `writer/verify_fill.py` | 支持"只有表头"的模板 | 原模板 `fill_region = null` → 取下标直接崩；另外新补的行没有原样式可比，不该报差异 |
| `agent/api_server.py` | `/api/fill` 加 `require` 参数 | 用户要求从界面传进流水线（`A23_USER_REQ`），报告里会显示"行条件" |
| `pipeline.py` | 透传「用户要求 / 行条件 / 直通」三类日志 | 否则界面上只看到"填完了"，看不到"凭什么只填这些行" |
| `agent/web/index.html` | 填表卡片加「用户要求」输入框 | 不填就等于没有条件，用户得有个地方说这句话 |

两个细节值得单独记：

**① 筛行后行号不连续 → 写回会静默丢数据**
`build_slot_map` 原来用 `槽位 = 源行号 - 最小源行号`。COVID 筛完是"41 个国家各一段、
中间隔着大段没命中的行"，行号差算出来几千，全部 `>= 槽位数` 被丢掉 ——
表面现象是"抽取有 2542 条，写回只填了几行"。改成**排序去重后的名次**：
行号本来连续时名次 == 行号差，行为与改前完全一致（这是能直接换的前提）。

**② 只有表头的模板，验收脚本会崩**
`fill_region` 是 null，`fr["start_row"]` 直接 `TypeError`。顺带发现更隐蔽的一处：
补出来的 2542 行在原模板里**根本不存在**，拿空单元格的默认样式去比对，
报了 **15252 处格式差异**（假阳性）。现在只比原模板真实存在的行，新补行单独说明。

### 4.3 怎么判定"该不该走直通"（不硬来）

```
有行条件（用户要求里解析到 / A23_USER_REQ / A23_ROW_FILTER）
   └─ 源池里有表格，且模板每一列都能在源表里找到同名列（含别名、斜线拆分）
        ├─ 能 → 直通：按行号整列搬，0 次模型调用
        └─ 不能 → 日志写清"哪几列对不上"，回落原来的大模型路径
```

对不上就回落，是刻意的：**宁可慢，也不要用一个"看起来像"的确定性替换掉真正的抽取。**

`meta`：`pool_mb = 87.3`、`gate_weight = 2`（≥30MB → 占满闸门，**独占**，这是 11-03 那次

## 六、必须让你拍板的两件事

### 6.1 模板里没有「日期」列，2542 行丢了日期就分不清是哪天

模板 6 列：`国家/地区 | 大洲 | 人均GDP | 人口 | 每日检测数 | 病例数`。
按「日期区间」筛出来的 2542 行，同一个国家会出现 62 次（每天一次），
但**表里没有任何一列能告诉你这是哪天的**。

我按最忠实的口径做了（区间内有多少条就填多少条，顺序与源表一致），但这是三种可能里的第一种：

| 口径 | 行数 | 说明 |
|---|---|---|
| **A. 逐条搬（本次交付）** | 2542 | 区间内每条记录一行；信息最全，但行内看不出日期 |
| B. 每国一行 | 41 | 取区间内最后一天（8/31）的快照；表更"像报表"，但丢掉 61 天 |
| C. 逐条搬 + 加一列「日期」 | 2542 | 建议做法：模板缺这一列是模板的问题，加一列信息才完整 |

**要不要我按 C 加一列「日期」？** 一句话就行。

### 6.2 docx 那 31 个省，这次没并进去（口径不同，不敢自己决定）

- docx 是**叙述体**，没有「日期一列」——按字面口径它不参与筛选（全文只有 2020-07-27 一个日期，落在区间内）；
- 它的单位与 xlsx 差 10000 倍：`人均GDP 7.3 万元`、`人口 5775 万`、`检测量 12.6 万份`，
  而 xlsx 是 `5353.2`、`2873457`、`269`；
- 更麻烦的是语义：docx 的「病例数」是**当日新增**（湖北 0、新疆 57），
  xlsx 的「病例数」是**累计**（Albania 2580→2662 递增）。硬塞进同一列，这一列就废了。

所以这次只交了 xlsx 的 2542 行。如果你要 docx 也进来，我需要你定两件事：
**单位按谁的口径换算**（万元→元 我按 1 万算）、**新增和累计混不混列**（建议新增另起一列）。

## 八、这次学到的一条（写进纪律）

> **"值一致"只证明写回没抄错，不证明抽取对。**
> 判断一份真实数据填得对不对，必须绕开流水线、从源表独立重算一遍。

基线那 15 行、31.8 秒、6/6 列成功、来源一致 —— 五项指标全绿，一条都不对。
真实数据的价值就在这里：它不骂你，它只是让你在"全绿"里交一份错的。
