# 聊天室（用户端多人交流）· 实现与验收记录

日期：2026-10-25
范围：用户端新增「💬 聊天室」入口 —— 一个公共大群，所有登录用户都能在里面交流。
不改动模块 1/2/3 的任何逻辑，也不影响客服（AI / 人工）那套会话。

## 一、怎么用

1. 顶栏点「💬 聊天室」（在「意见反馈」左边），右下角弹出面板。
2. 面板顶部是群名和在线人数；下面一排是当前在群里的人，点名字就在输入框插入 `@昵称 `。
3. 输入框 Enter 发送、Shift+Enter 换行；单条最多 500 字，同一个人 1 秒内只能发一条。
4. 鼠标移到自己的消息上会出现「撤回」，5 分钟内的可以撤回，别人看到的是「这条消息已撤回」。
5. 点右上角 × 收起面板：自己从在线名单里消失（不是等 45 秒过期），
   之后群里有人说话，顶栏「聊天室」上会出现红色未读角标，下次打开自动清零。
6. 聊天室面板和客服面板都在右下角，互相自动让位，不会叠在一起。

## 二、代码在哪

| 文件 | 改动 |
| --- | --- |
| `agent/room.py` | 新增：两张表 + 发消息 / 轮询 / 撤回 / 在线心跳 / 统计 |
| `agent/api_server.py` | 新增 4 个接口：`/api/room/poll`、`/api/room/send`、`/api/room/recall`、`/api/room/leave`；启动时建表 |
| `agent/web/index.html` | 顶栏入口 + 聊天室面板（HTML/CSS/JS）+ 未读角标 |
| `README.md` | 界面一节补了聊天室截图与说明 |

两张表（`room.ensure_tables()` 幂等建表）：

- `room_messages`：id / user_id / user_name / avatar / content / kind / deleted / created_at。
  昵称和头像存的是快照，但读取时 JOIN `users` 取最新的：改了昵称头像，历史消息也跟着变。
- `room_online`：user_id 主键 / user_name / avatar / joined_at / last_seen。
  每轮轮询心跳一次，45 秒没心跳算掉线；`leave` 直接删行。

几个设计选择：

- **轮询而不是 WebSocket**：和客服模块同一套形态（一个 uvicorn 进程 + 线程池），
  2.5 秒一轮只取 `after_id` 之后的新消息，接口响应只有几百字节；面板收起时降到 6 秒，
  并且带 `alive=0`，只看有没有新消息、不把自己算在线。
- **撤回怎么通知别人**：撤回不产生新 id，增量拉取发现不了。用一个「已撤回条数」当版本号
  `rev`，客户端发现 rev 变了就整段重拉（群里消息量小，一次就够）。
- **防刷屏为什么不用数据库时间**：`created_at` 是秒级 DATETIME，
  S.9 秒发一条、S+1.1 秒再发，库里算出来差 1 秒，实际只隔 0.2 秒。
  所以以进程内单调时钟为准（1 秒一条），数据库同秒判断只做重启后的兜底。
- **乐观上屏 + 认领**：沿用客服面板的做法 —— 消息先上屏，等服务端回执回来按 id "认领"，
  不会出现一条消息显示两遍。

## 三、验收结果

### 1. 接口（`聊天室-接口验收-1025.py`，26 项全过）

三个独立 cookie 会话模拟三个人同时在线：注册进群 → 在线名单互相可见 → A 发言 B/C 都收到 →
1 秒内连发被拒 → 501 字被拒 → @ 提及 → 撤回（rev 变化、别人看到已撤回）→
撤别人的被拒 → 收起面板后从在线名单消失、alive=0 不算在线 → 计数与字段齐全。

跑法：`python 收尾对照\聊天室-接口验收-1025.py --port 8010`
（脚本自带清场：测试账号、测试消息、在线记录都会删掉。）

### 2. 真机浏览器（`聊天室-浏览器验收-1025.py`，31 项全过）

Edge headless + CDP，注入登录态后真的点一遍：打开面板 → 在线名单 / 自己带「我」→
界面发消息（乐观上屏、回执挂 id、不重复、有撤回按钮）→ 另一个账号在群里说话，
2.5 秒内收到且 @我 高亮 → 点名字自动 @ → 撤回变占位 →
收起面板后别人发言出现未读角标 → 重新打开历史还在、角标清零 → 全程 0 条 JS 报错。

截图：`agent\输出\聊天室-1-面板.png`、`聊天室-2-未读角标.png`；
README 用的干净截图（三个内置演示账号对话）是 `docs\screenshots\08-聊天室.png`。

### 3. 过程中修掉的 3 个问题

1. 前端请求封装写成了不存在的 `crGet` / `crPost`（实际叫 `csGet` / `csPost`），
   面板一直显示「群里暂时连不上」—— 现在共用一套，并留了注释。
2. 面板刚打开时，「收起状态的 6 秒轮询」和「进群整段拉取」会互相覆盖渲染：
   出现过在线名单少了自己、空白没有提示。现在整段拉取期间挂 `loading` 锁，
   另加「按 user_id 兜底判断自己」和「每轮补一次空态」。
3. 前端限速只看数据库秒级时间，同秒内连发偶尔漏判 —— 改成进程内单调时钟。

## 四、已知限制

- 一个公共大群，没有分群 / 私聊 / 图片 / 表情包；单条 500 字。
- 2.5 秒轮询，人多时消息可能有 1~2 秒延迟（和客服模块的取舍一致）。
- 在线人数靠心跳，关闭浏览器不会立刻消失，最多 45 秒后过期。
- 群里现在有 3 条演示对话（林同学 / 周姐 / 客服小张），想清空直接删 `room_messages` 里的行即可。

## 五、改完要重启服务

`agent/api_server.py` 加了新接口，旧的 8000 进程不会自动生效：
关掉「启动操作台」的黑窗口，重新双击项目根目录的 `启动操作台.bat`。
（页面 HTML 改的是静态文件，刷新即可；但接口必须重启进程。）
