# 组会之后，用户端能摸到的改进（附操作示例）

> 对照基准：10-22 那次组会时的系统。下面每条都是**在浏览器里点得出来、看得见结果**的，
> 不讲内部指标，只讲"你点哪里、说什么、会看到什么"。
> 配套：`组会汇报-A23\不足项改进对照-1105.md`（内部验收口径，含证据文件）

## 0. 先做一件事：重启服务（不重启，一半新功能看不到）

现在 8000 端口上跑的是 **11-03 20:27 启动**的那个进程。手写 OCR、并发自动降级、
填表的「用户要求」都是在这之后写进代码的 —— **进程不重启，代码还是老的**。
症状：界面上按钮都在（前端是每次刷新加载），但点下去行为跟组会前一模一样。

**30 秒确认是不是旧进程**：浏览器打开

```
http://127.0.0.1:8000/api/knowledge/stats
```

- 返回里有 `"by_kind"` 和 `"by_domain"` → 新代码，可以往下看
- 返回 `{"detail":"Not Found"}` → **旧进程**（说明连"统一知识抽取"都没有），按下面重启

再打开 `http://127.0.0.1:8000/api/ocr/status` 交叉确认：

- 返回里有 `"handwriting": true` → 手写那部分也是新的
- 只有 `ok / engine / low_conf_threshold / tip / pdf` → 旧进程

**重启**：
1. 关掉那个黑色命令行窗口（标题 `启动操作台`，窗口里能看到 `uvicorn running on ...`）
   或者在任务管理器里结束这两个 PID：`41896`、`8924`
2. 双击项目根目录的 `启动操作台.bat`
3. 浏览器打开 `http://127.0.0.1:8000` → 会先到登录页

登录：内置账号 `2482991994` / `123456`（三个身份都有权限）；
没建过就在登录页点「注册一个」现场建。

## 一、上传自己的模板，填完就能下载（10-26 新增）

**组会前**：只有系统自带那 5 张 xlsx + 5 张 docx，想填自己的表没入口。

**现在**：xlsx / xlsm / docx 拖进去就能用。

1. 顶栏点「📋 表格填写」
2. 点「⬆ 上传模板」，选 `测试数据\模板上传\COVID-19 模板.xlsx`
   （也可以直接把文件**拖进这个弹窗**，会显示一片蓝框）
3. 下拉框里出现 `COVID-19 模板.xlsx`，说明传成功了
4. 点「开始填写」→ 等 10~40 秒 → 出现 `✓ 填写完成` + 报告 + 「⬇ 下载已填写表格」

清理：同面板「🗂 我上传的模板」→ 逐条删。
系统自带的删不掉（会提示"系统模板不允许删除"），同名再传会被拒（409）。

## 二、一句话说要求，只填符合条件的数据（11-04，最值得演示的一条）

**组会前**：填表没有"条件"这个概念。文档库里有什么就抽什么，抽多少算多少 ——
拿 COVID 那单举例，组会前的行为是**填 15 行 2020 年 2 月的数据，还报"成功"**。

**现在**：填表面板多了一个「用户要求」输入框，写了条件就按条件筛。

1. 先确认文档库里有 `COVID-19全球数据集（节选）.xlsx`（1.5 万行）
   没有就顶栏「📥 导入文档」加进去
2. 「📋 表格填写」→ 选 `COVID-19 模板.xlsx`
3. 在「用户要求」里**原样粘贴**这一句（注意末尾那个句号不影响）：

```
智能填表，将两个文件的内容中日期一列从2020/7/1到2020/8/31的数据填入模板中.
```

4. 点「开始填写」

**期望在报告里看到**：

| 看到什么 | 说明 |
|---|---|
| `行条件 日期 ∈ [2020-07-01, 2020-08-31]` | 它真的读了你这句要求 |
| `结构化直通：整列搬运 ... 0 次模型调用` | 模板列名和源表一样，不需要模型猜 |
| `写入 2542 行` / 15252 格一致 | 41 国 × 62 天，逐格可核 |
| 全流程 18~20 秒 | 不填要求走大模型是 31 秒、15 行、错的 |

**不填要求会怎样**：走老的大模型路径，慢、少、错。这个对比本身就是最好的演示。

## 三、扫描件、手机照片、手写 → 认字（10-26 新增，11-03 补手写）

**组会前**：只认电子版 docx / xlsx / md / txt。扫描件直接说"读不了"。

**现在**：
- 扫描版 PDF：逐页判有没有文字层，只有扫描页才走 OCR（电子版 PDF 不白跑）
- 手机拍的照片：歪 0.6° + 噪点也能认
- **工整手写**：印刷表格里的手写填值、整篇手写、页边横躺的批注

1. 顶栏「🔎 文字识别」
2. 拖入 `测试数据\OCR样本\手写\手写-验收单（印刷表格+手写填值）.png`
3. 2~4 秒出结果 →「复制全文」可以直接粘走；「并入文档库」之后就能对它下指令、跑提取
4. 再试 `测试数据\OCR样本\扫描版-采购合同.pdf`（3 页扫描件，约 12 秒）

**手写改好的证据**：那张验收单的「数量」列会读出 `3` 和 `2`。
组会前这两格是**整格消失** —— 不是模型不认识，是默认阈值把低分字丢了。

仍认不出的（别在这上面浪费时间）：连笔草书、手写签名、印章。

**组会前**：单机测试页，没有登录、没有角色、没有别人。

| 三种身份 | 打开 `127.0.0.1:8000` 先到登录页 | 用户端 / 客服端 / 管理员端 三张卡片选一个进 |

## 八、同时提交几个填表任务，不会互相拖死（11-03 新增）

**组会前**：三个任务一起跑，最重的那个从 43 秒变 126 秒（同时超 90 秒红线）。

**现在**：按文档库大小自动决定 —— 库小就并行，库大就一个跑完再跑下一个，
并且大库上每个任务自动降到 4 列，不再互相抢。

1. 开三个浏览器标签，都进「📋 表格填写」
2. 分别选 `模板1` / `模板4` / `模板5`，几乎同时点「开始填写」
3. 关注三件事：三个页面都出 `✓ 填写完成`；没有哪个越等越久；
   接口返回的 meta 里能看到 `pool_mb` 和 `gate_weight`（库大时 `gate_weight` 会等于总名额，也就是独占）

这条路靠的是**调度**，不是单任务变快 —— 单任务该 16 秒还是 16 秒。

## 十一、数据仓库里直接上传文档（11-05 新增，当前最新）

**为什么加**：以前「🗄 数据仓库」只能看提取结果，文档进不来 —— 想加文档得回主界面找输入框左边的「📥 导入文档」，不少人根本不知道那个按钮在哪。

**怎么做**
1. 顶栏点「🗄 数据仓库」
2. 上半部分就是「📚 文档库」：`共 N 份（我上传的 X · 标准库 Y）`
3. 点「⬆ 上传文档」，或把文件直接拖进虚线框（可多选）
4. 传完立刻出现在**第一行**并加粗，右侧带 `TXT · 129 B · 2026-11-05 19:56` 这样的明细
5. 想立刻抽数据：点这一行右边的「🧠 提取入库」→ 后台跑统一知识抽取（读懂结构 → 抽值 → 入库）→ 完成后上面的数字、下面的表格自动刷新

**看到什么算成功**
- 提示「✓ 1 份已进文档库」，并写出识别成的格式、块数、耗时
- 顶部计数 +1（顶栏「文档库 N 份」也同步）
- 这一行有「我上传的」蓝色标签 —— 我上传的永远排在标准库前面
- 同名再传一次会自动存成 `xxx(2).docx`，**原文件绝不覆盖**
- 对 `.exe` 这类不支持的格式直接报错，并列出当前支持哪些，不会静默收下

**支持的格式**：docx / xlsx / pdf / md / txt / png / jpg / bmp / webp / tif
（扫描版 PDF 和图片自动走 OCR，页多的慢一些）

**验证记录**（都不是"看起来对"，是机械跑的）
- `收尾对照\文档库上传-验收-1105.txt` —— 后端 35/35：明细字段、上传落盘、解析、重名策略、池内可见、非法格式拒绝、清理还原
- `收尾对照\文档库上传-界面验收-1105.txt` —— 真机 27/27：headless Edge 里真点、真传、真刷新，截图在 `agent\输出\文档库-1-面板.png` / `文档库-2-上传完成.png`

## 十二、不再分「实体 / 画像 / 字段」，一条线读懂任意文档（11-05 新增，当前最新）

**为什么换**：原来那三条线，本子上写的是"实体、画像、字段"，用户看到的却是三个复选框——
勾哪个、区别在哪，说不清。更实际的问题是：三条线各自带着一套"我预设要抽什么"的念头，
**换一个行业就不准**。医疗报告里的"检验项目"、判决书里的"案号"、BOM 里的"物料编码"，
在旧的三条线里找不到位置。

**现在的做法**：不预设。分两步走——

1. **先读懂这份文档自己的结构**：它里面有哪些"对象"（一份检验报告里是「检验报告」「检验项目」；
   一份判决书里是「法院」「原告」「被告」「判决结果」），每个对象有哪些"属性"
   （列头、`案号：`这种标签、表格的列名）。这一步只问模型一句话，但要求它**只能从这份文档里
   看到的东西**归纳，看到什么说什么，看到 6 个对象就写 6 个，看到 0 个就写 0 个。
2. **再照着这个结构把值抽出来**：表格类直接按列头逐格读（**不经过模型，100% 是原文**）；
   叙述类（合同正文、判决理由）才交给模型，且**每个值都必须能在原文里逐字找到**，找不到就丢。

**怎么用（三个入口，随便哪个）**

| 入口 | 操作 |
|---|---|
| 数据仓库 | 顶栏「🗄 数据仓库」→ 文档库某一行右边「🧠 抽取知识」→ 抽完自动跳进这份文档的知识视图 |
| 识别入库 | 顶栏「🔎 识别入库」→ 勾文档 → 填「关注点」→ 点「开始自动抽取」 |
| 一句话 | 主输入框直接说：`自动读懂设备采购合同.docx并抽取关键信息入库，重点关注付款方式和交期` |

**「关注点」是干什么的**：你写"重点关注床位和农村"，命中的条目会打上 `focus` 标记，
在知识库列表里排在前面、带标记。**不写也能抽全量** —— 它只是排序和标记，不是过滤器。

**看到什么算成功**

```
◆ 领域：民政事业统计 ｜ 类型：统计公报
◆ 对象：民政服务机构和设施×3属性 ｜ 行政区划单位×2属性 ｜ 社区综合服务机构和设施×5属性 …
◆ 入库条目：32 条 ｜ 对象 0 · 属性 26 · 关系 0 · 事件 0 · 要点 6
◆ 值可核：33/33 = 100.0%（逐条回原文/单元格）
◆ 关注点命中：床位、农村 ｜ 13 条
```

数据仓库里的表格也从"实体/画像/字段"三张表，变成一张按 **对象 · 属性 · 关系 · 事件 · 要点**
分组的知识表；顶部计数显示"对象 N / 属性 N / 关系 N / 要点 N"。

### 12.0 数据仓库按文档看：点进去，只看这一份（11-05 晚新增）

**为什么加**：以前所有文档的条目混在一张表里，翻十页也找不到"中国新冠这份到底抽到了什么"。

现在文档库每一行就是一个入口：

### 12.1 叙述体文档（一段一条记录）也能逐条抽

`测试数据\源文档\docx\中国COVID-19新冠疫情情况.docx` 就是这种：没有表格、没有「案号：」这种标签，
纯粹是 31 段散文，**一段说一个省**（"湖北省常住人口约 5775 万人，人均 GDP 约 7.3 万元，
7 月 27 日实现……全零报告，核酸检测量约 12.6 万份"）。

这种文档最早是**一条都抽不出来**的，踩了三个坑，现在都堵上了：

| 当时的现象 | 真正的原因 | 现在的做法 |
|---|---|---|
| 直接报"没有抽到可入库的内容" | 骨架扫不到列头/标签就直接放弃归纳 | 没标签也照样把正文喂给模型归纳——叙述体的结构就藏在句子里 |
| 31 个省只抽到 1 条属性 + 4 句总结 | 一次喂 31 段，模型偷懒只写总结 | 切成 16 段一批、2 批，逼它逐条照抄 |
| 关注点填了"日期"，结果只抽日期 | 模型把"关注点"当成"只抽这些" | 提示词里写明：关注点只用于标记，**清单里的属性全都要抽** |

**实测结果**（就是这份新冠文档，关注点=城市）：

```
◆ 领域：公共卫生疫情防控 ｜ 类型：疫情情况纪实报告
◆ 对象：省（省级行政区）×11属性 ｜ 全国疫情汇总×5属性
◆ 入库条目：192 条 ｜ 属性 181 · 事件 2 · 要点 9
◆ 值可核：181/181 = 100.0%（逐条回原文）
◆ 省级行政区：28 个（上海市、云南省、内蒙古自治区、北京市 … ）
用时 59 秒
```

**速度是怎么提上来的**（11-05 晚，86 秒 → 59 秒）

| 改了什么 | 效果 |
|---|---|
| 让模型别再抄一遍原文片段（`quote`），改成程序拿值反查原文 | 每条省 2/3 的字，输出量直接砍掉四成 |
| 属性名改成编号输出（`A3` 代替「常住人口」），同一记录的多属性合并成一条 | 输出量再砍一半 |
| 批次从 8 段×4 批改成 16 段×2 批 | 少掉两批的固定开销，36 秒（纯抽取） |

**一个必须知道的限制**：现在用的模型平台是**单并发**（同一时刻只处理一个请求），
所以"加线程并发"完全没用 —— 4 批再怎么并发也是排队。这也是为什么批数越少越快。
换到支持并发的平台（如硅基流动，免费额度、并发 4），这份文档能压到 25 秒上下。

抽出来长这样（每条都带原文出处）：

```
省份（湖北省） ｜ 常住人口：约 5775 万人   ｜ 第 3 段
省份（湖北省） ｜ 人均 GDP：约 7.3 万元      ｜ 第 3 段
省份（湖北省） ｜ 新增确诊病例：全零报告     ｜ 第 3 段
省份（湖北省） ｜ 核酸检测量：约 12.6 万份   ｜ 第 3 段
```

**关于"抽日期"这件事要说清楚**：这份文档的日期是**全局的**（全部 31 个省都是 2020 年 7 月 27 日），
所以日期只记了 1 条挂在「全国疫情概况」上，**没有给每个省重复挂一遍**——
重复挂 31 遍同一个日期，只会让数据库变脏，不会多出信息。
如果你要的是"每条记录都带日期"的宽表（省份 × 日期 × 指标），那是**填表**那条线（模块3）的活，
不是知识抽取的活。

**要诚实说的三件事**

- **版面式表格会跳过，不会硬读**：有些政府公报是从 PDF/Word 转过来的，一个单元格里塞了十几条
  数据（`数量：34 4 23 5 2 2843…`）。这种表宁可标注「※ 版面式，已跳过」，也不输出一坨糊在一起的值。
- **关注点只认"名字对得上"的**：你写"重点关注超标项"，如果文档里根本没有叫"超标"的属性，
  它不会硬编一个，报告里会写一句"关注点在本文档里没有直接对应的项"。
- **旧的三条线没删**：你明确说「抽实体」「出画像」时还走旧路径（老验收脚本靠它），
  但**默认全部走新的一条线**。
- **同一份文档跑两次，"对象怎么划分"可能不一样**：比如判决书里的「诉讼请求」，
  这次可能被建成一个对象、下次被建成「判决书」的一个属性。**值不会丢**，只是挂的位置不同。
  这也是为什么验收里"结构命中"允许"对象位或属性位都算"——考核的是"有没有认出这块信息"，不是"必须按某一种建模方式"。
- **条数多的叙述体会慢一些**：31 段 × 8 属性这种文档现在是 **35~60 秒**
  （同一份文档快慢会飘，因为对面平台是单并发、高峰要排队）。
  合同、判决书、会议纪要这类一般 20~40 秒。表格类几乎瞬间（不调模型）。
  提速的唯一办法是少抽（加并发没用，实测并发调高反而更慢，服务端会排队）。
